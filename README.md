# Luxive Agency Management(営業管理システム・動作するモック)

本部と代理店のあいだで、同じ企業・施設への営業が重ならないように管理する画面一式です。
仕様書「Luxive Agency Management 統合仕様書」(`docs/spec.md`)をそのまま動く形にしたフロントエンド単体のモックです。

## 要点

- **見せられる現物です。** ブラウザで開けば、本部・代理店管理者・代理店一般ユーザーの3つの立場をその場で切り替えて触れます。
- **データはブラウザの中だけ。** localStorage に保存し、外部へは一切送信しません。企業名・担当者名・電話番号・URLはすべて架空です。
- **判定ロジックは1か所。** 営業可否照会と営業予定登録は同じ重複判定関数を通ります。ダッシュボードのカードと内訳一覧も同じ集計関数を使います。
- **自動テスト291件。** 仕様書§21の受入テストを、ドメイン・ロジックのテスト183件、公開ゲートのテスト37件、ブラウザテスト71件で自動検証しています。

## 動かし方

```bash
npm install
npm run dev
```

`http://localhost:5183` を開くとログイン画面が出ます。試したい立場を選んでください。パスワードはありません。

| 立場 | 例 | 見える範囲 |
| --- | --- | --- |
| 本部管理者 | 大槻 志保 | 全代理店の案件・重複審査・商品マスター・基本設定・監査ログ |
| 代理店管理者 | 芝田 直人(株式会社リンクスプロモーション) | 自社の案件全部・自社ユーザー管理・引継ぎ |
| 代理店一般ユーザー | 遠藤 千尋(同上) | 自分の担当案件の編集・自社の他担当者案件は閲覧のみ |

左下の「データ初期化」でいつでも初期状態に戻せます。

## ひととおり試す道すじ

1. **遠藤 千尋**でログイン →「営業可否照会」で `東都ホテル` と入れて照会 → 重複の可能性ありになる(既存の「東都ホテル株式会社」と企業名が一致するため)
2. 続けて `株式会社ミドリ湯` / `0463-77-1234` / `https://midoriyu.example.jp` で照会 → 重複なし →「営業予定登録へ進む」
3. 引き継がれた値のまま担当者を入れて登録 → 保護期限30日が付いて登録完了
4. 案件詳細で商談へ進める → 保護期限が90日へ伸びる。見積金額・受注金額を入れると受注確定になり365日へ
5. **大槻 志保**(本部)でログイン →「重複審査」で待ちの3件を比べる → 承認 / 営業不可 / 差し戻しを選ぶ
6. 申請した本人(西野 真紀など)でログイン →「通知・申請履歴」に結果が届いている。同じ代理店の他の人には届かない

## 中身の構成

```
src/
  domain/      判定・計算のロジック(画面から独立。テストはここが中心)
    normalize.ts   企業名・電話番号・Webサイトの正規化(§3.4)
    duplicate.ts   重複判定の共通関数(§4)
    protection.ts  保護期間の計算(§10)
    dealOps.ts     案件の更新操作(§11〜§13)
    dashboard.ts   ダッシュボード集計(§18)
    permissions.ts ロール別の閲覧・編集判定(§2)
    products.ts    商品マスター連携(§7)
    companies.ts   企業・施設への集約(§16)
  data/        localStorage への保存と、画面から呼ぶ操作(store)
  router/      hash ルーティングとロール別アクセス判定(§2.4)
  screens/     画面
  components/  共通UI
docs/          仕様書・実装メモ・受入テスト対応表・スクリーンショット
tests/unit/    ドメインの自動テスト(Vitest)
tests/e2e/     ブラウザの自動テスト(Playwright)
```

## 本番化するときに置き換えるところ(§20.2)

| いまのモック | 本番 |
| --- | --- |
| localStorage | 認証済みAPI + サーバー側認可 + RLS |
| sessionStorage(照会の引継ぎ) | 同上(サーバー側のドラフト) |
| 商品画像の Data URL | クラウドストレージ |
| メールは状態だけ保持 | 実メール配信 |
| ブラウザの時刻 | サーバー時刻 |
| 監査ログもlocalStorage | 追記のみの不変ストレージ |

`src/domain/` は画面にもストレージにも依存しないため、そのままサーバー側へ移せます。
localStorage は開発者ツールから直接書き換えられます。フロントエンド単体のモックでは防げないため、本番では必ずサーバー側で判定してください。
