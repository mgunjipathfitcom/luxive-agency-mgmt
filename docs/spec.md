# Luxive Agency Management 統合仕様書

> 受領した仕様書の原文を、章立てを保ったまま Markdown 化したもの。実装の正本はこの文書とする。
> 実装上の解釈・補足は `docs/implementation-notes.md` に分けて記録する。

## 1. 文書概要

### 1.1 目的

本システムは、Luxive本部と代理店の間で、営業案件の重複防止、営業活動、案件保護、提案・見積・受注、追加受注、代理店ユーザー、顧客情報を一元管理する営業管理システムである。

主要な目的は次のとおり。

- 同じ企業・施設に複数代理店が重複営業することを防止する。
- Reserved案件、有効受注案件、保護中案件を適切に判定する。
- 営業予定登録から受注確定までの進捗と活動履歴を管理する。
- 案件の保護期間を本部基本設定に従って自動計算する。
- 商品マスターと提案・見積・受注情報を連携する。
- 本部、代理店管理者、代理店一般ユーザーごとに閲覧・編集範囲を制御する。
- ダッシュボードと案件一覧・詳細で同じ集計データを使用する。

主要業務フローは、次の5段階を維持する。

営業可否照会 → 営業予定登録 → 商談 → 見積提出 → 受注確定

内部ステータスも、この5段階を基準に管理する。

## 2. 利用者と権限

### 2.1 本部管理者

本部管理者は次の操作を行える。

- 全代理店の案件閲覧・編集
- 全企業・施設の閲覧
- 重複審査
- Reserved案件管理
- 商品マスター管理
- 代理店管理
- 代理店ユーザーの閲覧
- 保護期間・重複スコアなどの基本設定
- 所属代理店変更などの本部専用操作
- 監査ログ閲覧
- 全体ダッシュボード集計

本部管理者向け主要メニューは、ダッシュボード、重複審査、案件管理、代理店、代理店ユーザー、企業・施設、Reserved案件管理、商品マスター、延長申請、問い合わせ管理、通知、基本設定とする。

### 2.2 代理店管理者

代理店管理者は次の操作を行える。

- 自社案件の閲覧・編集
- 自社ユーザーの新規登録・編集
- 招待・再送
- 利用停止・再開
- 在籍状態管理
- パスワード再設定案内
- 担当案件の個別・一括・全件引継ぎ
- 自分が行った営業可否照会・申請の通知閲覧
- 本部への問い合わせ

他代理店の案件、企業、ユーザー、金額、履歴は閲覧できない。

### 2.3 代理店一般ユーザー

代理店一般ユーザーは次の操作を行える。

- 自分の担当案件を閲覧・編集
- 自社の他担当者案件を閲覧専用で確認
- 営業可否照会
- 営業予定登録
- 自分が行った申請の通知・履歴閲覧
- 本部への問い合わせ

他代理店の情報は閲覧できない。

ロールごとの案件閲覧・編集判定は共通関数で管理する。

### 2.4 URL・戻る操作を含む権限制御

- メニューを非表示にするだけでなく、現在ロールに許可されていないページはRouterでも拒否する。
- hashの直接入力、検索条件変更、選択状態、ブラウザの戻る操作から権限を迂回できないこと。
- 案件詳細を開く際にも、選択された案件IDに対して閲覧権限を再確認する。
- 現在の画面ルーティングでは、ロール別メニュー判定をRouterでも実施する。

## 3. 営業可否照会

### 3.1 画面名

営業可否照会（簡易バージョン）

### 3.2 位置づけ

営業予定登録前に行う簡易的な重複チェックである。画面には次の趣旨を明示する。

> 営業可否照会は簡易チェックです。営業予定登録時には必須項目を含めて再度重複チェックを行うため、営業可否照会で問題がなくても営業予定登録時に重複審査となる場合があります。

### 3.3 入力項目

| 項目 | 必須 | 備考 |
| --- | --- | --- |
| 企業名 | 必須 | 企業名だけでも照会可能 |
| 施設名 | 任意 | 特定施設を識別する場合に使用 |
| 電話番号 | 任意 | 必須マークを表示しない |
| Webサイト | 任意 | 入力された場合は形式検証 |

### 3.4 入力値の正規化

**企業名** — 比較時には次の差異を吸収する。

株式会社 / 有限会社 / 合同会社 / 医療法人 / 社団法人・財団法人 / （株）、(株)、㈱ / 全角・半角 / 大文字・小文字 / 空白 / 句読点・記号

表示上は入力された企業名を使用し、正規化値は内部判定用とする。

**電話番号** — 次の表記差を吸収する。

ハイフン / 空白 / 括弧 / +81 / +81 (0) / 0081 / 内線表記

正規化後は国内形式の数字列として比較する。

**Webサイト** — 次の差異を吸収する。

http:// / https:// / www. / 大文字・小文字 / URLパス / 末尾スラッシュ / 末尾ドット

単一ラベルや不正なホスト名は有効なドメインとして扱わない。

## 4. 重複判定

### 4.1 共通判定関数

営業可否照会と営業予定登録は、同じ重複判定関数を使用する。

営業可否照会でclearだった場合でも、営業予定登録時に編集後の企業名、施設名、電話番号、Webサイトで必ず再判定する。簡易照会結果を最終判定として流用してはならない。

### 4.2 判定優先順位

1. **Reserved案件一致** — 結果: reserved / 表示: Reserved案件・営業不可 / 重複審査へ送らない
2. **有効な受注案件一致** — 結果: ordered / 表示: 受注案件・営業不可 / 重複審査へ送らない
3. **正規化企業名完全一致** — 結果: similar / 表示: 重複の可能性あり・重複審査待ち / スコア・閾値に関係なく必ず重複候補
4. **スコア判定** — 電話番号、Webドメイン、施設名、企業名類似などを加点。閾値以上ならsimilar
5. **いずれにも該当しない** — 結果: clear / 自動承認

### 4.3 4区分

| 内部値 | 利用者向け表示 | 処理 |
| --- | --- | --- |
| clear | 重複なし：自動承認 | 本部承認不要 |
| similar | 重複の可能性あり：重複審査待ち | 本部審査へ登録 |
| reserved | Reserved案件：営業不可 | 即時停止 |
| ordered | 受注案件：営業不可 | 即時停止 |

### 4.4 企業名完全一致の特例

正規化企業名完全一致はスコア判定より優先する。たとえば次は同一企業として扱う。

株式会社Luxive / Luxive / Ｌｕｘｉｖｅ（株）

旧localStorageに次の設定が残っていても、必ずsimilarにする。

```
company weight = 40
duplicate threshold = 50
```

つまり、企業名一致を40点として閾値未満でclearにすることは禁止する。

### 4.5 保護期限切れ企業

保護期限切れで営業禁止ではない場合、即営業不可にはしない。ただし、正規化企業名が同じ過去案件が存在する場合はsimilarとする。

本部重複審査では「有効保護中」と「保護期限切れ」を明確に区別する。期限切れ受注案件も、有効受注としては即停止しないが、過去登録企業として企業名一致候補には含める。

### 4.6 重複可能性スコア

候補ごとに0〜100%の補助スコアを表示する。スコア項目の初期例は次のとおり。

| 比較項目 | 初期ウェイト例 |
| --- | --- |
| 法人格等を除いた企業名 | 50 |
| 電話番号 | 25 |
| Webドメイン | 20 |
| 施設名 | 5 |

本部基本設定から閾値・ウェイトを変更可能とする。ただし、正規化企業名完全一致の専用判定は設定変更の影響を受けない。

スコアは審査補助であり、自動的な最終判断ではない。候補には一致項目、不一致項目、推奨判定も付与する。

## 5. 営業可否照会から営業予定登録への遷移

### 5.1 遷移条件

clearの場合のみ「営業予定登録へ進む」を表示する。

### 5.2 引継ぎ項目

企業名 / 施設名 / 電話番号 / Webサイト の4項目を引き継ぐ。引継ぎ先ではすべて編集可能とする。現在はsessionStorageのeligibilityDraftを使用して引き継ぐ。

### 5.3 引継ぎデータの扱い

- 営業予定登録を開いた時点で引継ぎ値を初期値として使用する。
- 送信時は画面上の最新値を使用する。
- 登録処理開始時に引継ぎ用データを削除する。
- 過去の引継ぎ値が次の申請へ残らないこと。

## 6. 営業予定登録

### 6.1 必須項目

| 項目 | 必須 |
| --- | --- |
| 企業名 | 必須 |
| 電話番号 | 必須 |
| Webサイト | 必須 |
| 担当者 | 必須 |
| 施設名 | 任意 |
| 提案商品 | 任意 |

簡易照会とは異なり、電話番号とWebサイトの必須仕様を維持する。

### 6.2 Webサイト

- 「Webサイト」の必須マークを表示する。
- 「Webサイトなし」は表示しない。
- 未入力または不正形式の場合は登録不可。
- 表示用入力値と正規化ドメインを分離保存する。

### 6.3 登録時の再判定

登録ボタン押下時に、現在入力されている最新値で重複チェックを必ず再実行する。結果別の処理は次のとおり。

**clear** — 自動承認 / 案件を作成 / 営業予定登録後の保護期間を設定 / 登録完了画面へ遷移

**similar** — 重複審査待ちとして案件を作成 / 本部の重複審査一覧へ登録 / 登録者本人の申請履歴へ保存

**reserved / ordered** — 営業不可 / 通常案件として進行させない / 判定履歴と監査ログを保存

### 6.4 登録完了画面

表示項目: 「営業予定の登録が完了しました」/ 企業名・施設名 / 提案商品 / 判定結果 / 設定された保護期間 / 保護期限

操作: 案件詳細を確認する / 続けて別の営業予定を登録する / 担当案件一覧へ戻る

二重送信を防止する。

## 7. 商品マスター

### 7.1 管理項目

SKU／内部ID / ブランド / 商品分類 / 商品名 / 香り / サイズ / 商品説明 / 商品画像 / 販売状態 / 備考

ただし、代理店ユーザー向けの選択・入力単位は商品名とし、SKU、香り、サイズを入力させない。

### 7.2 販売状態

**販売中** — 新規入力の対象とする。営業予定登録 / 新規提案 / 新規見積 / 新規受注 / 追加受注 / 案件詳細の新規入力行

**停止中** — 新規入力の選択肢から除外する。ただし、過去に登録済みの次のデータは削除しない。案件 / 提案 / 見積 / 受注 / 追加受注 / 金額履歴

販売中商品の取得は、商品マスターをactiveで絞り、商品名を一意化して使用する。

### 7.3 動的反映

本部が新しい販売中商品を追加した場合、コード修正なしで次へ反映する。営業予定登録 / 案件詳細 / 提案・見積・受注情報 / 追加受注

### 7.4 過去商品とのマージ

案件詳細の商品行は「案件に保存済みの商品行」と「現在販売中の商品マスターの商品名」の2種類をマージする。これにより、新商品は既存案件詳細へ追加、停止商品は過去案件内で維持、の両方を実現する。

### 7.5 商品画像

JPG、PNG、WebP / 最大容量検証 / アップロード前後プレビュー / 変更・削除 / 画像なしの場合の共通代替画像 / モックではData URLで保存 / 本番ではクラウドストレージへ差し替え可能な構造

## 8. 案件一覧・検索・並び替え

### 8.1 本部の代理店絞り込み

企業名 / 施設名 / 担当者 / 案件ステータス / 提案商品名 / 所属代理店

## 9. 案件詳細

### 9.1 表示順

基本情報 → 保護情報 → 案件進捗・営業活動 → 提案・見積・受注情報 → 変更履歴

### 9.2 PC・モバイル配置

PC: 左に基本情報、右に保護情報。スマートフォン・タブレット: 基本情報 → 保護情報 の順で縦表示する。

### 9.3 基本情報

担当営業は案件引継ぎからのみ変更する。

## 10. 保護期間

### 10.1 基本設定

| 起点 | 保護日数 |
| --- | --- |
| 営業予定登録 | 30日 |
| 商談 | 90日 |
| 見積提出 | 90日 |
| 受注確定 | 365日 |
| 追加受注 | 365日 |

日数単位へ統一し、「12か月」と「365日」を混在させない。

### 10.2 営業予定登録

変更日を保護開始日とする / 基本設定のplannedDaysを参照 / 変更日から30日後を初期期限とする

### 10.3 商談

変更日からmeetingDays後 / 既存期限の方が長い場合は短縮しない

### 10.4 見積提出

変更日からquotedDays後 / 既存期限の方が長い場合は短縮しない

### 10.5 受注・追加受注

受注日を保護開始日とする / 受注日からorderDays後 / 最終受注日を更新 / 追加受注でも同じ計算を行う

### 10.6 残り日数

残り日数は保存しない。`保護期限 - 現在日` で毎回算出する。保護計算は共通関数を利用する。

### 10.7 基本設定変更

本部管理者は、設定変更を既存案件に反映するか選択できる。

- 反映しない: 新規案件・次回ステータス変更から使用
- 反映する: 既存案件を再計算し、変更履歴へ保存

## 11. 案件進捗・営業活動

### 11.1 入力項目

活動日 / 案件ステータス / 営業活動内容 / 登録者

### 11.2 保存パターン

ステータス変更のみ / 営業活動のみ / ステータス変更と活動の同時保存

同一時系列として次を保存する。活動日 / 変更前ステータス / 変更後ステータス / 活動内容 / 登録者 / 登録日時 / 変更に伴う保護期限

税区分は表示しない。

## 12. 提案・見積・受注情報

### 12.1 表示単位

商品マスターの商品名単位。表示列は 商品名 / 提案対象 / 見積金額 / 受注金額。

### 12.2 金額

商品ごとに入力 / 見積合計を自動計算 / 受注合計を自動計算 / 空欄と0円を区別 / 負数を禁止 / 数字以外を拒否 / スマートフォンで数字キーボード / 上下スピナーを表示しない / 保存済み表示は3桁区切り

### 12.3 履歴

保存時点のスナップショットとして次を保存する。登録日 / 見積日 / 受注日 / 商品名 / 提案対象 / 見積金額 / 受注金額 / 見積合計 / 受注合計 / 初回受注／追加受注 / 登録者 / 登録日時

過去履歴を上書きしない。履歴はボタンを押した場合のみ表示する。

## 13. 追加受注

### 13.1 入力

受注日 / 販売中商品ごとの受注金額 / 受注合計 / 登録者

### 13.2 保存

初回受注を上書きしない / 追加受注イベントとして追加 / 案件全体受注額へ加算 / 最終受注日を更新 / 受注日から365日後へ保護期限更新 / ダッシュボードへ反映

### 13.3 商品名スナップショット

追加受注時の商品名を履歴に保存する。商品マスターの商品名が後から変更・停止されても、過去追加受注の表示名を変更しない。

## 14. 本部重複審査

### 14.1 比較画面

次の2領域を明確に分ける。

**既に登録されている情報** — 企業名 / 施設名 / 電話番号 / Webサイト / 登録済み代理店 / 担当者 / ステータス / 保護状態 / 保護期限 / 登録日

**今回新しく登録された情報** — 企業名 / 施設名 / 電話番号 / Webサイト / 申請代理店 / 登録者 / 登録日時 / 提案商品 / 重複可能性 / 判定理由

### 14.2 表示ルール

一致・類似項目を色・アイコンで強調 / 候補をスコア降順で表示 / 有効保護／期限切れを区別 / 正規化企業名は主要項目として表示しない / 正規化値は「判定の詳細」に格納 / 推奨判定を表示（承認推奨 / 要確認 / 営業不可推奨）

### 14.3 本部操作

承認 / 営業不可 / 差し戻し / メッセージ入力

メッセージ必須条件: 承認は任意 / 営業不可は必須 / 差し戻しは必須

### 14.4 審査履歴

操作日時 / 操作した本部ユーザー / 判定結果 / メッセージ

案件、申請履歴、通知、監査ログを同じ更新処理で整合させる。

## 15. 本人限定通知

### 15.1 通知対象

重複審査結果は、実際に照会・申請した本人だけに通知する。

通知しない対象: 申請代理店の管理者 / 同代理店の他ユーザー / 既存候補案件の代理店 / 既存案件の担当者 / 本人以外の代理店ユーザー

代理店管理者本人が申請した場合は、本人として通知する。

### 15.2 通知データ

通知ID / 通知種別 / 通知対象ユーザーID / 通知対象メールアドレス / メール送信状態 / 対象申請ID / 審査結果 / 本部メッセージ / 審査日時 / 既読日時 / 再申請可否

通知表示はrecipientUserIdの完全一致で絞る。

### 15.3 申請者向け情報

表示する: 申請日時 / 申請企業・施設 / 判定結果 / 本部メッセージ / 審査日時 / 再申請可否

表示しない: 既存案件の代理店 / 既存担当者 / 既存案件の連絡先 / 商談内容 / 見積金額 / 受注金額

## 16. 企業・施設

本部管理者向けの顧客マスターとして維持する。

### 16.1 検索

企業名 / 施設名 / 電話番号 / Webサイト・ドメイン / 所属代理店 / 担当営業 / 案件ステータス / 保護状態 / Reserved / 受注確定

### 16.2 企業詳細

基本情報 / 関連案件一覧 / 所属代理店・担当営業 / 保護状態・期限 / Reserved判定 / 受注有無 / 見積・受注金額 / 初回・追加受注履歴 / 重複判定履歴 / 変更履歴

案件管理は案件単位、企業・施設は企業単位として区別する。

## 17. 代理店ユーザー管理・引継ぎ

代理店ユーザー管理の主体は代理店管理者とする。

操作: 新規登録 / 氏名・メール・部署・権限編集 / 招待・再送 / 利用停止・再開 / 在籍中・休職中・退職済み / パスワード再設定案内 / 個別・一括・全件引継ぎ

引継ぎ履歴: 引継ぎ元 / 引継ぎ先 / 実行者 / 日時 / 対象案件

本部管理者は通常の登録・編集をせず、閲覧専用とする。

## 18. ダッシュボード

### 18.1 集計範囲

本部: 全代理店 / 代理店管理者: 自社 / 一般ユーザー: 自分の担当案件

### 18.2 有効契約・受注企業数

ステータスが受注確定 / 現在日が保護期限内 / 企業名でユニーク化

### 18.3 商談数

選択期間内に初めて次の段階へ到達した案件（商談 / 見積提出 / 受注確定）。

条件: 現在も保護期限内 / 案件単位で1件 / 後続ステータスへ進んでも減らさない / 商談を経由しない直接見積・受注も含む

### 18.4 見積金額

選択期間内 / 現在も保護期限内 / 最新の有効見積 / 取消・無効を除外 / 同じ履歴を重複集計しない

### 18.5 受注金額

選択期間内 / 受注確定 / 現在も保護期限内 / 初回受注＋追加受注 / 取消・無効を除外

### 18.6 保護期限間近

現在も保護期限内 / 基本設定の警告日数以内 / 期限切れは除外または別表示

カードと遷移先一覧は同じ集計関数を使用する。

## 21. 受入テスト仕様

最低限、次を自動検証する。

### 21.1 重複・簡易照会

- 東都ホテル株式会社と東都ホテル、電話・Web空欄でsimilar
- 旧company weight 40／threshold 50でも完全一致はsimilar
- 簡易照会は企業名だけで実行可能
- 簡易照会の電話番号に必須マークなし
- 営業予定登録の電話番号に必須マークあり
- 4入力を営業予定登録へ引継ぎ
- 引継ぎ後の編集値で再判定
- Reservedはreserved
- 有効受注はordered
- 期限切れ企業名一致はsimilar

ドメインテストでは、旧設定、法人格差、期限切れ通常案件、期限切れ受注案件を検証している。

### 21.2 商品マスター

- 販売中商品だけ営業予定登録へ表示
- 停止商品は新規入力へ非表示
- 販売中商品を追加すると登録・詳細へ自動反映
- 過去案件の停止商品は表示継続
- 過去金額履歴の商品名は表示継続
- 案件検索が商品名で動作
- 追加受注が販売中商品名を参照

### 21.3 審査・通知

- similarだけが本部審査へ入る
- 承認はメッセージなしで実行可能
- 営業不可・差し戻しはメッセージ必須
- 登録者本人だけに通知
- 同代理店の他ユーザーへ通知しない
- 既存担当者へ通知しない
- 申請者へ既存案件の機密情報を表示しない
- 再読み込み後も審査・通知・履歴を維持

### 21.4 既存機能回帰

保護期間 / 追加受注 / 案件進捗 / 営業活動 / ロール権限 / ダッシュボード / コンソールエラーなし / モバイル横方向オーバーフローなし
